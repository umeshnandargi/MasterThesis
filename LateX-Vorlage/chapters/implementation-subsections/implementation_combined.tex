\section{Implementation of the Common Gripper Optimization Framework}
\label{sec:gripper_optimization_framework}

\subsection{Software Architecture and Responsibilities}
\label{sec:optimization_framework_sc}
\label{sec:two_finger_framework}

The implementation separates candidate generation from gripper evaluation.
The optimizer selects a decision vector and passes it through an evaluation
client to the service associated with the chosen gripper problem. The service
reconstructs the design, performs the domain-specific evaluation, and returns
an ordered objective vector.

The shared base class, \texttt{BaseOptimization}, provides the problem
configuration, variable definitions, optimization direction, and evaluation
client. Two specialized classes implement the optimization approaches:
\begin{itemize}
    \item \texttt{EvolutionaryOptimizationProblem} connects the evaluation
          service to \texttt{pymoo}, using its interface for evaluating
          individual candidates;
    \item \texttt{BayesianOptimization} manages an \texttt{Ax} experiment and registers
          completed candidate evaluations as trials.
\end{itemize}
Here, a trial is an Ax record containing a candidate design and its evaluation
results. The evaluation client is represented by the
\texttt{EvaluationClient} class.

The evolutionary implementation uses a monitoring component, \texttt{HVCallback}, which records current-population hypervolume, optional
cumulative-archive hypervolume (HV), and the evaluation count after optimizer updates. The cumulative archive is optional, as its use can significantly
increase computational time, particularly in optimization problems with a higher number of objectives. The Bayesian implementation uses
\texttt{HypervolumeTracker}, which stores completed observations for cumulative hypervolume calculation. Both components monitor search progress
without changing candidate generation or terminating a run.

Figure~\ref{fig:common_class_diagram} summarizes the principal relationships.
The evolutionary class additionally implements pymoo's \texttt{ElementwiseProblem} and
the Bayesian class delegates candidate generation to the \texttt{Ax Client}.
The diagram shows application-level responsibilities rather than every method
or internal dependency of the external libraries.

\subsection{Configuration and Experimental Budgets}

Each optimization request specifies the workpiece, gripper problem, ordered
variables and bounds, objective count, optimization method, and evaluation
endpoint. Variable order is preserved when constructing the evaluation
request, and returned objective values are interpreted in their configured
order.

The evolutionary experiments use a population size of 100 and a termination
budget of 20,000 objective evaluations. The configured generation count of 200
provides the nominal budgeting basis for population-based runs; it is not an
independent stopping criterion in the experimental setup described here.
Termination instead depends on the actual evaluation count. Consequently,
the budget does not depend on how an algorithm defines a generation or how
many offspring it evaluates in one update.

Bayesian experiments perform 100 candidate-generation batches, requesting up
to 10 trials per batch. For this implementation, the existing generation-count
configuration setting stores the number of batches. The maximum requested
budget is therefore 1,000 evaluations. The realized count can be smaller if
Ax returns fewer than ten trials in a batch. No additional trials are requested
to compensate for such a shortfall.

The Bayesian budget is limited because model-based candidate generation
becomes time-consuming as observations accumulate, particularly beyond
approximately 50 batches in the observed runs. This is a computational-budget
choice, not a convergence criterion.

The two approaches therefore share the evaluation pipeline but not the same
total evaluation budget. Progress is compared at common evaluation counts
where available, and final results are interpreted together with their
respective budgets and wall-clock times.

\subsection{Evolutionary Algorithm Setup}
\label{sec:two_finger_initialization}

NSGA-II, NSGA-III, CMOPSO, and SMS-EMOA use a population size of 100.
For MOEA/D, population size is determined by the number of reference
directions rather than by a separate population-size setting.
Consequently, 100 reference directions are generated to match the population
size of the other algorithms. Its neighborhood size is also set to 100,
covering the complete population and avoiding a narrower local restriction
on information exchange.

Reference directions are required by NSGA-III and MOEA/D. Their generation
method is selected according to objective count and algorithm:
\begin{itemize}
    \item For problems with at least four objectives, the \texttt{energy}
          method generates 100 reference directions.
    \item MOEA/D always uses \texttt{energy} with 100 directions, including
          the three-objective suction problem.
    \item For NSGA-III with three objectives, \texttt{das-dennis} is used
          with 99 partitions.
\end{itemize}

The choice of \texttt{energy} for higher-dimensional objective spaces avoids
the rapid growth of the Das--Dennis construction. For a fixed partition count,
the number of Das--Dennis directions increases rapidly with the number of
objectives, substantially increasing reference-direction generation and
processing costs. This is particularly relevant to the ten-objective
two-finger problem. The \texttt{energy} method instead allows the direction
count to remain fixed at 100. Both methods are briefly described in
Section~\ref{sec:reference_direction_generation}.

\subsection{Bayesian Algorithm Setup}

The Bayesian implementation creates an Ax experiment and registers the four
continuous decision variables as floating-point ranges with their configured
bounds.

Objectives are numbered sequentially, following the order of the vector
returned by the evaluation service. All gripper objectives are configured
for maximization.

The application does not specify a custom generation strategy, Sobol sample
count, surrogate model, kernel, or acquisition function. Ax manages
initialization and the transition to its modular BoTorch model using its
defaults. These settings are therefore not presented as manually chosen
experimental hyperparameters. The workflow diagram denotes the default
initialization and model-based stages as Sobol and MBM (modular BoTorch model), respectively.

For each of the 100 batches, the implementation requests up to ten new
candidate trials from Ax. The returned candidates are evaluated one at a time,
and each trial is immediately marked as completed with its observed objective
values. The next batch is requested only after the current batch has been
processed. Batch size therefore controls candidate requests, not concurrent
evaluation.

Design-space tolerances, objective-space tolerances, hypervolume stagnation,

corresponding to at most 1,000 completed evaluations.

\subsection{Hypervolume Monitoring}
\label{sec:two_finger_monitoring}

Hypervolume is calculated using \texttt{pymoo}'s indicator implementation.
All indicator inputs use the minimization convention internally.
The reference point has value $-0.1$ in every objective dimension in the natural maximization convention.
Because the original KPIs are non-negative, this reference point is worse
than the evaluated outcomes.

\subsubsection{Evolutionary optimization.}
The evolutionary monitoring component records two distinct series:
\begin{itemize}
    \item \textbf{Current-population hypervolume:} calculated from the feasible
          objective vectors in the population retained at the current optimizer
          update. This series may decrease.
    \item \textbf{Cumulative-archive hypervolume:} calculated from a persistent
          non-dominated archive. After each optimizer update, feasible
          population and offspring vectors are merged into the archive,
          and dominated vectors are removed. This series represents the
          best-so-far objective coverage encountered by the monitoring
          component and is non-decreasing, apart from numerical round-off.
\end{itemize}

The monitoring component also records the optimizer's cumulative evaluation
count. This provides the appropriate evaluation coordinate when algorithms
evaluate different numbers of offspring per update.

\subsubsection{Bayesian optimization.}
Only cumulative hypervolume is calculated. After each completed trial,
the tracker stores the observed objective vector. During result serialization,
hypervolume is calculated for successively longer prefixes of this observation
history. Each entry therefore corresponds to one completed evaluation,
although the series is computed from the stored history at the end.

The tracker internally negates the maximization observations and reference
point before calculating hypervolume. It does not alter the observations
supplied to Ax or stored in the Bayesian frontier.

Comparisons use the same reference point and objective scaling within a given
workpiece problem.

\subsection{Result Storage and Repeated-Run Evaluation}
\label{sec:common_output}

Each run produces a JSON-compatible result containing:
\begin{itemize}
    \item problem and optimization metadata;
    \item the available algorithm-configuration information;
    \item returned non-dominated decision vectors and objective values;
    \item hypervolume progression;
    \item total optimization wall-clock time.
\end{itemize}

The general hypervolume-history field contains the current-population series
for evolutionary runs but the cumulative series for Bayesian runs.
Evolutionary results additionally contain a separate cumulative-archive
hypervolume field. The stored series must therefore be interpreted according
to the optimizer family.

The evolutionary frontier consists of the decision vectors and corresponding objective values returned by the optimizer at termination. It must not be
confused with the monitoring component's cumulative archive: the final returned frontier can have lower hypervolume than the best-so-far archive. The
complete frontier archive is not stored due to computational limitations. For Bayesian optimization, Ax identifies the Pareto-frontier trials. The
implementation uses the stored observations associated with those trials where available; otherwise, it uses the objective metric means returned by
Ax.

These outputs are finite-search approximations rather than guarantees of
the global Pareto front.

Since the true reference front is unknown, IGD+ is evaluated against an
empirical non-dominated reference set assembled from repeated runs of the
same workpiece and algorithm. This provides a within-problem,
within-algorithm measure of the coverage of the reference approximation,
with lower values preferred. It is not an absolute distance to the unknown
true Pareto front, and values based on different empirical reference sets
are not directly comparable.

The repeated-run processing exports rankings and summary statistics, using
IGD+ as the primary ranking measure and final cumulative hypervolume as a
tie-breaker. Hypervolume plots distinguish the cumulative series from the
current-population series. Where sufficient repeated runs are available,
median and interquartile-range summaries are also produced.

\subsection{Decision Variables and Bounds for Multi-Suction Cup Gripper}
\label{sec:multi_sc_decision_variables}

The optimization is performed over the reduced decision vector and
all four variables are continuous.

The decision variables and their configured bounds are summarized in
Table~\ref{tab:multi_sc_variables}. For a suction-cup diameter of
$0.01\,\mathrm{m}$ (adopted from the suction-cup configuration
employed in the bin-picking demonstration conducted by Fraunhofer IPA), 
the configured lower radial bound is
$0.005\,\mathrm{m}$ for all workpieces and is calculated using equation \ref{eq:r_min}. The upper radial bound depends on
the workpiece. All angular variables use the interval $[0,2\pi)$;
the upper endpoint is excluded.

The radial search interval is expressed as
\begin{equation}
    r \in [r_{\min},r_{\max}].
\end{equation}
The radial bounds are determined separately for each workpiece.
The workpiece is oriented such that its longest dimension lies in the
horizontal plane, the horizontal bounding box is centred at
$(x,y)=(0,0)$, and the base of the workpiece is placed at $z=0$.
This establishes a consistent coordinate system for defining the
gripper-design bounds.

\begin{equation}
    \begin{gathered}
        r_{\max}
        =
        \min
        \left\{
            |X_{\min}|,\,
            |X_{\max}|,\,
            |Y_{\min}|,\,
            |Y_{\max}|
        \right\},
        \\[4pt]
        X_{\min},\, X_{\max},\, Y_{\min},\, Y_{\max} \in \mathbb{R},
        \\[2pt]
        X_{\min} \le X_{\max},
        \quad
        Y_{\min} \le Y_{\max},
        \\[2pt]
        r_{\max} \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\}.
    \end{gathered}
\end{equation}

The geometric definition of the lower radial bound is based on the
suction-cup radius $r_{\mathrm{cup}}$:
\begin{equation}
    \label{eq:r_min}
    \begin{gathered}
        r_{\min}
        =
        \frac{2\sqrt{3}}{3}\,
        r_{\mathrm{cup}},
        \\[4pt]
        r_{\mathrm{cup}},\, r_{\min}
        \in
        \left\{ r \in \mathbb{R} \mid r \ge 0 \right\}.
    \end{gathered}
\end{equation}
This lower bound corresponds to the circumradius of an equilateral
triangle with side length $2r_{\mathrm{cup}}$, i.e.\ the configuration
in which neighbouring cups just touch.

All optimization methods generate candidate values within these bounds.
In the evolutionary algorithms, the initial population is obtained by
random sampling and subsequently modified through the operators of the
selected algorithm. In Bayesian optimization, Ax first evaluates the
centre of the search space and then uses Sobol sampling to generate an
initial space-filling design. After sufficient initialization data have
been collected, Ax transitions to model-based Bayesian optimization.

\nomenclature{$r_{\min}$}{Lower radial bound for suction-cup placement}
\nomenclature{$r_{\max}$}{Upper radial bound for suction-cup placement}
\nomenclature{$r_{\mathrm{cup}}$}{Suction-cup radius}

\subsection{Evaluation of Multi-Suction Cup Gripper}
\label{sec:multi_sc_api_evaluation}

Each candidate is sent to the external evaluation API as the reduced
decision vector $\mathbf{q}_{\mathrm{SC}}=[r,\alpha_1,\alpha_2,\alpha_3]$. The server maps this vector to the Cartesian cup
configuration $\mathbf{P}=\Phi(\mathbf{q}_{\mathrm{SC}})$, generates and
filters grasps, and returns the objectives defined in \ref{sec:multi_sc_objective_evaluation}:

Algorithm~\ref{alg:multi_sc_api_evaluation} summarizes one evaluation request.

\begin{algorithm}[H]
\caption{API evaluation of a multi-suction cup gripper candidate}
\label{alg:multi_sc_api_evaluation}
\begin{algorithmic}[1]
\Require Candidate $\mathbf{q}_{\mathrm{SC}}$, fixed coordinate $z_0$,
         and configured workpiece
\Ensure Objective vector $\mathbf{f}(\mathbf{q}_{\mathrm{SC}})$
\State Send $\mathbf{q}_{\mathrm{SC}}$ to the evaluation API
\For{$i=1,2,3$}
    \State Construct cup position
           $\mathbf{p}_i =
           \left(r\cos(\alpha_i),\,r\sin(\alpha_i),\,z_0\right)$
\EndFor
\State Assemble the Cartesian configuration
       $\mathbf{P}=\Phi(\mathbf{q}_{\mathrm{SC}})$ from the cup positions
\State Generate suction grasp candidates for $\mathbf{P}$
\State Retain grasps that pass seal-formation and collision checks
\State Cluster the retained grasps
\State Compute $D$, $\hat{n}_{\mathrm{g}}$, and $\hat{A}$
\State Return $\mathbf{f}(\mathbf{q}_{\mathrm{SC}})
       = [D,\hat{n}_{\mathrm{g}},\hat{A}]$
       to the selected optimization framework
\end{algorithmic}
\end{algorithm}

\subsubsection{Grasp Evaluation}
\label{sec:grasp_eval_sc}

The evaluation service constructs the Cartesian gripper configuration
$\mathbf{P}=[\mathbf{p}_1,\mathbf{p}_2,\mathbf{p}_3]$ from the received
decision vector and computes the grasp-quality measures through the
following procedure.

     \subsubsection{Candidate Grasp Generation and Feasibility Filtering}

    Suction grasp candidates are generated using a method developed by Fraunhofer IPA, following the
    automatic suction grasp generation procedure described by~\cite{Kleeberger}. Points are
    uniformly sampled on the surface of the workpiece, and each sampled point defines a candidate
    grasp through its position and local surface normal. The local surface normal determines the
    approach direction of the suction cup.

    In the original method, each suction grasp candidate is tested for feasible seal formation using
    a quasi-static spring model of a suction cup, as introduced in~\cite{SC_quasi_static}. If the
    grasp point is considered feasible, the candidate is further tested with a gripper collider
    model for collisions between the gripper and the object.

    In this thesis, the method is extended to a gripper with three suction cups. For each candidate gripper pose, the seal-formation test is
    performed for all three suction cup contact positions $\mathbf{p}_1$, $\mathbf{p}_2$, and $\mathbf{p}_3$. A candidate is considered feasible only
    if all three suction cups form a sufficient seal. Each feasible candidate is subsequently subjected to a geometric collision check: the gripper
    geometry is represented by a sampled point set, transformed into the workpiece frame by the candidate pose, and tested for proximity against the
    workpiece point cloud. A candidate is rejected if any transformed gripper point lies closer than the clearance threshold of $\delta_{\mathrm{clr}} =
    0.5\,\text{mm}$ (adopted from the bin-picking demonstration conducted by Fraunhofer IPA) to any workpiece point. The candidates that pass both the
    seal-formation and the collision checks form the set of valid grasps $\mathcal{H}_{\mathrm{valid}}$, which is the input to the subsequent
    clustering step.

    \subsubsection{Clustering of Valid Grasps}

    The set $\mathcal{H}_{\mathrm{valid}}$ typically contains many grasps that are nearly identical
    in position and orientation. If the number of valid grasps
    $n_{\mathrm{v}} = |\mathcal{H}_{\mathrm{valid}}|$ exceeds the clustering budget
    $K_{\mathrm{clst}} = 15$, the grasps are clustered using the greedy farthest-point sampling
    (FPS) algorithm of~\cite{gonzalez1985clustering}, which iteratively selects the grasp with the
    largest minimum distance to the already selected representatives; otherwise all valid grasps are
    retained. The value of $K_{\mathrm{clst}} = 15$ is selected to strike a balance between computational cost and obtaining a sufficiently large
    number of candidate grasps for meaningful diversity calculations.

    Since grasp poses combine a translational and a rotational component, the sampling operates on a
    combined pose metric in which the Euclidean distance between the grasp positions
    $\mathbf{x}_i \in \mathbb{R}^3$ is normalised by the diagonal extent of the axis-aligned
    bounding box of all candidates, and the difference between the orientations
    $\mathbf{R}_i \in SO(3)$ is measured as the geodesic angle normalised by $\pi$.
    With the resulting normalised terms $\hat{\rho}_{\mathrm{pos}}$ and $\hat{\rho}_{\mathrm{ori}}$
    and an orientation weight $w \in [0,1]$,
    \begin{equation}
        \label{eq:combined-metric}
        \begin{gathered}
            \rho_w(i,j) =
            (1 - w)\,\hat{\rho}_{\mathrm{pos}}(i,j) + w\,\hat{\rho}_{\mathrm{ori}}(i,j),
            \\[4pt]
            w \in [0,1],
            \\[2pt]
            \hat{\rho}_{\mathrm{pos}}(i,j),\,
            \hat{\rho}_{\mathrm{ori}}(i,j),\,
            \rho_w(i,j) \in [0,1],
            \quad
            \forall\, i,j \in \{1,\ldots,N\},
        \end{gathered}
    \end{equation}
    so that $w = 0$ corresponds to purely position-based and $w = 1$ to purely orientation-based sampling; here $w = 0.35$ is chosen to balance
    positional and orientational differences, with a greater emphasis on positional variation. All distances are evaluated on the GPU, which keeps the
    selection tractable for large candidate sets.

    The final number of representatives $K^{*}$ is not predefined but obtained from an elbow
    criterion on the covering radius recorded during sampling: selection stops as soon as the
    relative coverage gain of an additional representative falls below $\tau = 0.05$, bounded from
    above by $K_{\mathrm{clst}}$. The resulting subset
    $\mathcal{H}_{\mathrm{clst}} \subseteq \mathcal{H}_{\mathrm{valid}}$ with
    $|\mathcal{H}_{\mathrm{clst}}| = K^{*}$ is passed on to the diversity evaluation.

 


















\subsection{Objective Evaluation of Multi-Suction Cup Gripper}
\label{sec:multi_sc_objective_evaluation}

After grasp evaluation, each candidate layout is assigned the natural objective vector
\begin{equation}
    \mathbf{f}(\mathbf{q}_{\mathrm{SC}})
    =
    \left[
        D(\mathbf{P}),\;
        \hat{n}_{\mathrm{g}}(\mathbf{P}),\;
        \hat{A}(\mathbf{P})
    \right],
    \qquad
    \mathbf{P}=\Phi(\mathbf{q}_{\mathrm{SC}}).
\end{equation}

The three Objectives are calclated as follows : 
\subsubsection{Diversity Metric Calculation ($D(\mathbf{P}$))}

The diversity score combines spatial and rotational diversity:
\begin{equation}
    \label{eq:grasp_diversity}
    \begin{gathered}
        \begin{aligned}
            D &=
            \begin{cases}
                0, & n_{\mathrm{g}} < 2,\\[2pt]
                \operatorname{clip}_{[0,1]}
                \!\left(
                    \lambda D_{\mathrm{pos}}
                    + (1-\lambda) D_{\mathrm{rot}}
                \right), & n_{\mathrm{g}} \geq 2,
            \end{cases}
            \\[3pt]
            D_{\mathrm{pos}}
            &=
            (1-\beta_{\mathrm{cov}}) D_{\mathrm{spread}}
            + \beta_{\mathrm{cov}} D_{\mathrm{cov}},
            \\[3pt]
            D_{\mathrm{spread}}
            &=
            \frac{1}{Ms}
            \sum_{(i,j)\in\mathcal{I}}
            \|\mathbf{y}_{i}-\mathbf{y}_{j}\|_{2},
            \\[3pt]
            D_{\mathrm{cov}}
            &=
            \operatorname{clip}_{[0,1]}
            \!\left(
                \frac{1}{2M}
                \sum_{(i,j)\in\mathcal{I}}
                \left(
                    1-\hat{\mathbf{u}}_{i}^{\mathsf{T}}\hat{\mathbf{u}}_{j}
                \right)
            \right),
            \\[3pt]
            D_{\mathrm{rot}}
            &=
            \frac{1}{\pi M}
            \sum_{(i,j)\in\mathcal{I}}
            \rho_{\mathrm{geo}}(\mathbf{R}_{i},\mathbf{R}_{j}),
        \end{aligned}
        \\[4pt]
        n_{\mathrm{g}} \in \left\{ n \in \mathbb{Z} \mid n \ge 0 \right\},
        \\[2pt]
        \lambda,\, \beta_{\mathrm{cov}}
        \in \left\{ r \in \mathbb{R} \mid 0 \le r \le 1 \right\},
        \\[2pt]
        D,\, D_{\mathrm{pos}},\, D_{\mathrm{spread}},\,
        D_{\mathrm{cov}},\, D_{\mathrm{rot}}
        \in \left\{ r \in \mathbb{R} \mid 0 \le r \le 1 \right\}.
    \end{gathered}
\end{equation}

For $n_{\mathrm{g}} < 2$, the diversity score is set to zero, because at least
two grasps are required for a pairwise comparison. For $n_{\mathrm{g}} \geq 2$,
all pairwise terms are averaged over the set of unique grasp pairs
$\mathcal{I}$, which contains $M$ elements:
\begin{equation}
    \label{eq:grasp_pairs}
    \begin{gathered}
        \begin{aligned}
            \mathcal{I}
            &=
            \left\{ (i,j) \in \mathbb{N}^{2}
            \,\middle|\,
            1 \le i < j \le n_{\mathrm{g}} \right\},
            \\[3pt]
            M
            &=
            |\mathcal{I}|
            =
            \frac{n_{\mathrm{g}}(n_{\mathrm{g}}-1)}{2},
        \end{aligned}
        \\[4pt]
        M \in \left\{ m \in \mathbb{Z} \mid m \ge 1 \right\}.
    \end{gathered}
\end{equation}

The spatial terms use the grasp points $\mathbf{y}_{i}$ projected onto the
workpiece surface $\partial\mathcal{W}$. $D_{\mathrm{spread}}$ normalizes their
mean pairwise distance by the bounding-box diagonal $s$, where $\mathbf{e}$
contains the bounding-box side lengths. $D_{\mathrm{cov}}$ uses the direction
vectors $\hat{\mathbf{u}}_{i}$ from the workpiece centroid $\mathbf{o}$ :

\begin{equation}
    \label{eq:grasp_spatial_terms}
    \begin{gathered}
        \begin{aligned}
            \mathbf{y}_{i}
            &=
            \underset{\boldsymbol{\xi} \in \partial\mathcal{W}}{\arg\min}
            \|\boldsymbol{\xi} - \mathbf{x}_{i}\|_{2},
            \\[3pt]
            s
            &=
            \|\mathbf{e}\|_{2},
            \\[3pt]
            \hat{\mathbf{u}}_{i}
            &=
            \frac{\mathbf{y}_{i} - \mathbf{o}}
            {\|\mathbf{y}_{i} - \mathbf{o}\|_{2} + \varepsilon},
        \end{aligned}
        \\[4pt]
        \mathbf{x}_{i},\, \mathbf{y}_{i},\, \hat{\mathbf{u}}_{i},\, \mathbf{o}
        \in \mathbb{R}^{3},
        \quad
        \partial\mathcal{W} \subset \mathbb{R}^{3},
        \\[2pt]
        \mathbf{y}_{i} \neq \mathbf{o},
        \quad
        \forall\, i \in \{1,\ldots,n_{\mathrm{g}}\},
        \\[2pt]
        \mathbf{e} \in
        \left\{ \mathbf{v} \in \mathbb{R}^{3} \mid v_{k} > 0,\ k = 1,2,3 \right\},
        \\[2pt]
        s,\, \varepsilon \in \left\{ r \in \mathbb{R} \mid r > 0 \right\}.
    \end{gathered}
\end{equation}
The spread term rewards distance between grasps. The coverage term separates
grasps distributed around the object from grasps concentrated in one region.

The rotational diversity $D_{\mathrm{rot}}$ is the mean pairwise geodesic
distance between the grasp orientations, normalized by its maximum value $\pi$:
\begin{equation}
    \label{eq:grasp_geodesic}
    \begin{gathered}
        \begin{aligned}
            \rho_{\mathrm{geo}}(\mathbf{R}_{i},\mathbf{R}_{j})
            &=
            \cos^{-1}\!\left( \operatorname{clip}_{[-1,1]}(q_{ij}) \right),
            \\[3pt]
            q_{ij}
            &=
            \frac{\operatorname{tr}(\mathbf{R}_{i}^{\mathsf{T}}\mathbf{R}_{j}) - 1}{2},
        \end{aligned}
        \\[4pt]
        \mathbf{R}_{i},\, \mathbf{R}_{j} \in SO(3),
        \quad
        q_{ij} \in \mathbb{R},
        \\[2pt]
        \rho_{\mathrm{geo}}(\mathbf{R}_{i},\mathbf{R}_{j})
        \in \left\{ r \in \mathbb{R} \mid 0 \le r \le \pi \right\}.
    \end{gathered}
\end{equation}

The clipping function keeps the inverse-cosine argument in its valid range,
which guards against floating-point errors:
\begin{equation}
    \label{eq:clip-function}
    \begin{gathered}
        \operatorname{clip}_{[a,b]} :
        \mathbb{R} \rightarrow \left\{ r \in \mathbb{R} \mid a \le r \le b \right\},
        \\[2pt]
        z \mapsto \min\!\left( b, \max(a,z) \right),
        \\[4pt]
        a,\, b,\, z \in \mathbb{R},
        \quad
        a \le b.
    \end{gathered}
\end{equation}

    \subsubsection{Normalised Grasp Count ($\hat{n}_{\mathrm{g}}(\mathbf{P})$)}

    The grasp-count objective measures the number of grasps retained for
    evaluation, rather than the total number of feasible candidates.
    It rewards a larger retained grasp set under the configured clustering
    procedure. The count is taken from the same set used for diversity
    evaluation:
    \begin{equation}
        n_{\mathrm{g}} =
        \begin{cases}
            |\mathcal{H}_{\mathrm{clst}}|,  & \text{if clustering is performed},\\[2pt]
            |\mathcal{H}_{\mathrm{valid}}|, & \text{otherwise}.
        \end{cases}
    \end{equation}
    To keep this quantity comparable with the remaining objectives, it is expressed relative to the
    clustering budget $K_{\mathrm{clst}}$, which is the maximum number of
    grasps retained by the clustering stage,
\begin{equation}
    \label{eq:grasp_count_norm}
    \begin{gathered}
        \hat{n}_{\mathrm{g}} = \frac{n_{\mathrm{g}}}{K_{\mathrm{clst}}},
        \\[4pt]
        K_{\mathrm{clst}} \in \left\{ k \in \mathbb{Z} \mid k \ge 1 \right\},
        \\[2pt]
        n_{\mathrm{g}} \in \left\{ n \in \mathbb{Z} \mid 0 \le n \le K_{\mathrm{clst}} \right\},
        \\[2pt]
        \hat{n}_{\mathrm{g}} \in \left\{ r \in \mathbb{R} \mid r \in [0,1] \right\}.
    \end{gathered}
\end{equation}
    Since clustering is only applied when more than $K_{\mathrm{clst}}$ valid grasps exist, the
    condition $n_{\mathrm{g}} \leq K_{\mathrm{clst}}$ holds in both cases and the ratio is bounded
    by unity without further clipping. A value of one indicates that the layout produced at least as
    many valid grasps as the clustering budget permits, whereas a value of zero corresponds to a
    layout for which no valid grasp was found.
    \nomenclature{$\hat{n}_{\mathrm{g}}(\cdot)$}{Normalised grasp count of a gripper layout, i.e.\ the number of evaluated grasps divided by the clustering budget}

    \subsubsection{Normalized Area Calculation ($\hat{A}(\mathbf{P}$)}

    The area of the triangle formed by the three suction cups is computed from their Cartesian
    coordinates. With the planar coordinates $ \mathbf{P} = (p_{i,x},p_{i,y})$ of cup $i$,
    \begin{equation}
        \label{eq:cup_triangle_area}
        \begin{gathered}
            \begin{aligned}
                A(\mathbf{P})
                &=
                \frac{1}{2}
                \bigl|
                    (p_{2,x} - p_{1,x})(p_{3,y} - p_{1,y})
                \\
                &\qquad\quad
                    - (p_{3,x} - p_{1,x})(p_{2,y} - p_{1,y})
                \bigr|,
                \\[3pt]
                A_{\max}
                &=
                \tfrac{3\sqrt{3}}{4}\, r_{\max}^{2},
            \end{aligned}
            \\[4pt]
            A : \mathcal{P}_{\mathcal{W}} \rightarrow
            \left\{ r \in \mathbb{R} \mid 0 \le r \le A_{\max} \right\},
            \quad
            \mathbf{P} \in \mathcal{P}_{\mathcal{W}},
            \\[2pt]
            \mathbf{p}_{k} = (p_{k,x},\, p_{k,y})^{\mathsf{T}}
            \in \left\{ \mathbf{v} \in \mathbb{R}^{2} \mid \|\mathbf{v}\|_{2} \le r_{\max} \right\},
            \quad
            \forall\, k \in \{1,2,3\},
            \\[2pt]
            r_{\max} \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\}.
        \end{gathered}
    \end{equation}
The area is zero exactly when the three cups lie on one line. It reaches
$A_{\max}$ when they form an equilateral triangle on the circle of radius
$r_{\max}$.

    To make this objective comparable in magnitude with the remaining objectives, the area is
    normalised by the largest triangle area that can be realised within the admissible mounting
    region. The suction-cup reference points are restricted to a circle of radius $r_{\max}$, and
    the maximum-area triangle inscribed in a circle is the equilateral one, so that
    \begin{equation}
        \label{eq:cup_area_max}
        \begin{gathered}
            A_{\max} = \frac{3\sqrt{3}}{4}\, r_{\max}^{2},
            \\[4pt]
            r_{\max} \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\},
            \\[2pt]
            A_{\max} \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\}.
        \end{gathered}
    \end{equation}
    The radius $r_{\max}$ is not a global constant but is determined per workpiece as the largest
    circle that still fits inside the admissible mounting bounds. Consequently $\hat{A}$ expresses
    the achieved area relative to what is geometrically possible for that specific workpiece.

    The normalised area objective is therefore
    \begin{equation}
        \hat{A} = \frac{A}{A_{\max}} \in [0,1].
    \end{equation}

    This objective favours gripper layouts with a wider support polygon, which is associated with
    the assumption of improved grasp stability.
    \nomenclature{$A(\cdot)$}{Area of the triangle formed by the three suction cups of a gripper layout}
    \nomenclature{$\hat{A}(\cdot)$}{Normalised triangle-area objective of a gripper layout}
    \nomenclature{$A_{\max}$}{Maximum triangle area attainable within the admissible mounting circle}


Continuity considerations : The suction objectives are not guaranteed to be continuous in the
decision variables. Small layout changes can alter seal feasibility,
collision classification, the retained grasp count, or the
representatives selected by clustering. Abrupt changes can also occur
when the clustering threshold or elbow stopping criterion is crossed.

If fewer than two grasps remain for diversity evaluation, the pairwise
diversity components are set to zero. Thus, the evaluator samples
1,000 initial surface points to provide a dense candidate set. This reduces
dependence on sparse sampling but does not guarantee continuous
objectives or the existence of valid grasps.

\subsubsection{Grasp Set Definition}
\label{sec:grasp_set}

A grasp specifies the pose in which the workpiece is presented to the jaws. In the evaluation
pipeline, the gripper remains stationary in its nominal pose, and the workpiece is reoriented for
each grasp.

Only the orientation component of the generated grasp poses is used, since the relative
gripper--workpiece position is determined by the collision- and proximity-based placement search
described in Section~\ref{sec:grasp_eval}. A grasp $\gamma_i$ is therefore fully described by a
spatial rotation $\mathbf{R}_i$ applied to the workpiece,
\begin{equation}
    \label{eq:grasp_rotation}
    \begin{gathered}
        \mathcal{W}_i = \mathbf{R}_i\,\mathcal{W},
        \qquad
        i = 1,\ldots,n_{\mathrm{or}},
        \\[4pt]
        \mathbf{R}_i \in \mathrm{SO}(3),
        \quad
        \mathcal{W}_i \subset \mathbb{R}^{3},
        \quad
        \forall\, i \in \{1,\ldots,n_{\mathrm{or}}\},
        \\[2pt]
        \mathcal{W} \subset \mathbb{R}^{3},
        \quad
        n_{\mathrm{or}} \in \left\{ n \in \mathbb{Z} \mid n \ge 1 \right\}.
    \end{gathered}
\end{equation}
where $\mathcal{W}$ denotes the workpiece in its reference orientation. The translation components
of the generated poses are discarded. The grasp set is
\begin{equation}
    \mathcal{R}
    =
    \left\{
        \mathbf{R}_1,\ldots,\mathbf{R}_{n_{\mathrm{or}}}
    \right\},
    \qquad
    n_{\mathrm{or}} = 10 .
\end{equation}
\nomenclature{$\gamma_i$}{Grasp $i$ of the predefined grasp set}
\nomenclature{$\mathcal{R}$}{Set of predefined workpiece orientations of a two-finger optimization run}
\nomenclature{$n_{\mathrm{or}}$}{Number of predefined grasp orientations of a two-finger optimization run}
\nomenclature{$\mathcal{W}_i$}{Workpiece geometry in the orientation of grasp $\gamma_i$}

In the present study, $n_{\mathrm{or}} = 10$ orientations are configured. This value is selected as a compromise between optimization complexity and
having a sufficiently large number of grasps for evaluation.
The predefined grasps are spatially
spread subset of the physically admissible grasps of the given workpiece, which ensures that the
evaluated orientations are mutually dissimilar and at the same time realizable on the part geometry.

The grasp set is generated once before the optimization starts and is stored as part of the workpiece list. It is therefore identical for all
candidates and for all repetitions of a run, which makes the objective values of different candidates directly comparable. The orientations are fixed
quantities and are not optimization variables.

\subsubsection{Grasp Evaluation}
\label{sec:grasp_eval}

Following the proximity criterion in
Section~\ref{subsec:objective_two_finger_gripper}, the gripper is evaluated
for each grasp $\gamma_i$, $i=1,\ldots,n_{\mathrm{or}}$.
The gripper remains in its assembly pose while the workpiece is rotated
to the corresponding orientation. Both geometries are voxelized;
gripper surface voxels are closed by morphological dilation and hole
filling, with part labels retained to distinguish the jaws.

The modified Snuggle-Pack procedure computes an overlap map for each
jaw $j\in\{\mathrm{L},\mathrm{R}\}$ from its occupancy grid
$\chi_{\mathcal{J}_j}$ and the oriented workpiece grid
$\chi_{\mathcal{W}_i}$:
\begin{equation}
    \label{eq:snuggle_overlap}
    \begin{gathered}
        \zeta_{i,j}
        =
        \operatorname{DFT}^{-1}\!\left(
            \operatorname{DFT}(\chi_{\mathcal{J}_j})\,
            \operatorname{DFT}(\chi_{\mathcal{W}_i})
        \right),
        \qquad
        \zeta_{i,j}(\mathbf{v}) < \varepsilon_{\mathrm{col}}
        \;\Longleftrightarrow\;
        \mathbf{v} \text{ is collision-free},
        \\[4pt]
        \forall\, i \in \{1,\ldots,n_{\mathrm{or}}\},
        \quad
        \forall\, j \in \{\mathrm{L},\mathrm{R}\},
        \quad
        \forall\, \mathbf{v} \in \mathbb{Z}^{3},
        \\[2pt]
        \chi_{\mathcal{J}_j},\, \chi_{\mathcal{W}_i} : \mathbb{Z}^{3} \rightarrow \{0,1\},
        \quad
        \zeta_{i,j} : \mathbb{Z}^{3} \rightarrow \mathbb{R},
        \\[2pt]
        \varepsilon_{\mathrm{col}} \in \left\{ r \in \mathbb{R} \mid 0 < r < 1 \right\}.
    \end{gathered}
\end{equation}
Here, $\mathbf{v}$ is a discrete displacement and
$\varepsilon_{\mathrm{col}}$ absorbs single-precision FFT round-off.
Collision freedom refers only to the voxelized jaw model; the gripper
base is excluded. Padding to a common grid size makes the transform cyclic.

Each overlap map is convolved with a one-sided Gaussian kernel along
the jaw's closing direction, favouring placements where a small closing
motion would establish contact. Kernel standard deviations are converted
from millimetres to voxel units using the voxel edge length. Only the
width and height deviations affect the score because the kernel acts
in the plane orthogonal to the gripper length axis. Colliding
displacements are excluded.

For each position in the length--height plane, the jaws independently
select their best collision-free closing-axis positions. Maximizing
their summed proximity over the plane yields $p_i$: both jaws share
the length--height placement but move independently along the closing
axis. FFT computations use GPU-accelerated PyTorch. The score is
dimensionless, unnormalized, and Gaussian-weighted; it measures neither
distance nor voxel count and depends on workpiece geometry and voxel
resolution.

The difference between the selected jaw positions defines the signed
opening width $\delta_i$. Negative values indicate closing onto the
workpiece; non-negative values require opening beyond the modelled
position. Only the sign is tested, not the magnitude relative to the
stroke. The returned KPI is
\begin{equation}
    \label{eq:grasp_k}
    \begin{gathered}
        k_i(\mathbf{q}_{\mathrm{PJ}})
        =
        \begin{cases}
            p_i(\mathbf{q}_{\mathrm{PJ}})/100,
                & \delta_i(\mathbf{q}_{\mathrm{PJ}})<0,\\[2pt]
            0, & \delta_i(\mathbf{q}_{\mathrm{PJ}})\geq0,
        \end{cases}
        \qquad i=1,\ldots,n_{\mathrm{or}},
        \\[4pt]
        p_i(\mathbf{q}_{\mathrm{PJ}}) \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\},
        \quad
        \forall\, i \in \{1,\ldots,n_{\mathrm{or}}\},
        \\[2pt]
        \delta_i(\mathbf{q}_{\mathrm{PJ}}) \in \mathbb{R},
        \quad
        k_i(\mathbf{q}_{\mathrm{PJ}}) \in \left\{ r \in \mathbb{R} \mid r \ge 0 \right\},
        \quad
        \forall\, i \in \{1,\ldots,n_{\mathrm{or}}\}.
    \end{gathered}
\end{equation}
Initial unscaled KPI values typically ranged from 0 to 200.
Division by 100 reduces objective magnitudes and makes the resulting
ten-objective hypervolume realizable.

Feasibility is assessed independently per grasp. An infeasible
orientation receives zero, the worst non-negative objective value,
rather than imposing a hard constraint on the entire candidate.

\subsection{Objective Evaluation of Two-Finger Gripper}
\label{sec:two_finger_objective_evaluation}

The evaluation service returns one grasp-quality KPI for each configured grasp. Since each optimization run considers a single workpiece and its
associated set of grasps, the number of objectives is directly determined by the size of the grasp set, resulting in ten objectives.
The individual KPIs are not aggregated into a scalar value; each grasp retains its own objective,
which preserves the information about which orientations a given contour favours.

Since a larger proximity KPI represents a better grasp result, the natural optimization problem is
\begin{equation}
    \begin{gathered}
        \max_{\mathbf{q}_{\mathrm{PJ}}\in\mathcal{Q}}
        k_i(\mathbf{q}_{\mathrm{PJ}}),
        \qquad i=1,\ldots,n_{\mathrm{or}},\\[4pt]
        \mathcal{Q}\subset\mathbb{R}^{4},
        \qquad n_{\mathrm{or}}=10,\\[2pt]
        k_i:\mathcal{Q}\rightarrow
        \mathcal{K}\subseteq\mathbb{R}_{\geq 0}
    \end{gathered}
\end{equation}
with the objective vector
\begin{equation}
    \mathbf{f}(\mathbf{q}_{\mathrm{PJ}})
    =
    \begin{bmatrix}
        k_1(\mathbf{q}_{\mathrm{PJ}}) &
        k_2(\mathbf{q}_{\mathrm{PJ}}) &
        \cdots &
        k_m(\mathbf{q}_{\mathrm{PJ}})
    \end{bmatrix}^{\mathsf{T}}
    \in\mathbb{R}_{\geq 0}^{m}.
\end{equation}
\nomenclature{$k_i(\cdot)$}{Grasp-quality KPI (\texttt{max\_prox}) of grasp $\gamma_i$}

Because the four decision variables define a single jaw contour that is shared by all grasps, the
objectives are generally conflicting: a contour whose depth profile conforms closely to the
workpiece in one orientation does not necessarily conform in the remaining ones. The optimization
therefore yields Pareto-optimal contours that represent different compromises in geometric
conformity across the ten predefined orientations.
